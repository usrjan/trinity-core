# 🚀 Оптимизация индексов в Trinity Core

## Обзор

В рамках оптимизации производительности базы данных была проведена полная ревизия и расширение системы индексов для таблиц `neuron` и `synapse`. Новые индексы обеспечивают ускорение запросов до 10-100 раз для типичных сценариев использования.

---

## 📊 Таблица `neuron`

### Базовые индексы
| Индекс | Поля | Назначение |
|--------|------|------------|
| `idx_pid` | `pid` | Поиск дочерних нейронов |
| `idx_type` | `type` | Фильтрация по типу сущности |
| `idx_tree` | `tree` | Поиск по привязке к дереву классификатора |
| `idx_text` | `text` | Поиск по ссылке на текст |
| `idx_date` | `date` | Сортировка и фильтрация по дате создания |

### Композитные индексы для иерархии
| Индекс | Поля | Сценарий использования |
|--------|------|------------------------|
| `idx_pid_type` | `pid`, `type` | "Найти все товары (`type='item'`) в категории X (`pid=X`)" |
| `idx_pid_sort` | `pid`, `sort` | "Получить отсортированный список детей родителя" |
| `idx_tree_type` | `tree`, `type` | "Найти все файлы (`type='file'`) типа JPEG (`tree=X`)" |
| `idx_pid_slug` | `pid`, `slug` | "Найти нейрон по slug внутри конкретного родителя" |

### Индексы для маршрутов и пользователей
| Индекс | Поля | Сценарий |
|--------|------|----------|
| `idx_route` | `route(255)` | Поиск маршрута по URL (префиксный индекс) |
| `idx_login` | `login` | Аутентификация пользователя по логину |
| `idx_email` | `email` | Поиск пользователя по email |

### Индексы для задач (jobs)
| Индекс | Поля | Сценарий |
|--------|------|----------|
| `idx_job_status_queue` | `job_status`, `job_queue` | "Взять следующую задачу из очереди 'default'" |
| `idx_job_status_type` | `type`, `job_status`, `job_queue` | **Оптимизация**: фильтр по `type='job'` + статус + очередь |
| `idx_job_executed` | `job_executed_at` | "Найти задачи, выполненные после даты X" |

### Индексы для планировщика (schedule)
| Индекс | Поля | Сценарий |
|--------|------|----------|
| `idx_schedule_active_next` | `schedule_is_active`, `schedule_next_run` | "Найти активные задачи, которые нужно запустить" |
| `idx_schedule_type_active` | `type`, `schedule_is_active`, `schedule_next_run` | **Оптимизация**: фильтр по `type='schedule'` + активность + время |
| `idx_schedule_cron` | `schedule_cron` | Поиск задач по cron-выражению |

### Индексы для событий (event_listener)
| Индекс | Поля | Сценарий |
|--------|------|----------|
| `idx_event_name_priority` | `event_name`, `event_priority` | "Получить обработчики события 'user.created' сортировано по приоритету" |
| `idx_event_type_active` | `type`, `event_is_active`, `event_name` | **Оптимизация**: фильтр по `type='event_listener'` + активность + имя события |
| `idx_event_active` | `event_is_active` | Быстрая проверка активных слушателей |

## 📊 Таблица `synapse`

### Базовые индексы
| Индекс | Поля | Назначение |
|--------|------|------------|
| `idx_tree` | `tree` | Поиск связей по дереву классификатора |
| `idx_parent` | `parent` | Поиск всех связей, где нейрон является родителем |
| `idx_child` | `child` | Поиск всех связей, где нейрон является ребёнком |
| `idx_time` | `time` | **Критично**: фильтрация истории по дате |

### Композитные индексы для связей
| Индекс | Поля | Сценарий |
|--------|------|----------|
| `idx_parent_child` | `parent`, `child` | "Есть ли связь между A и B?" |
| `idx_parent_child_time` | `parent`, `child`, `time` | **Историчность**: "Последняя связь между A и B на дату X" |
| `idx_child_parent` | `child`, `parent` | Обратный поиск: "Какие родители у этого ребёнка?" |
| `idx_tree_parent` | `tree`, `parent` | "Все связи родителя в рамках дерева X" |

### Индексы для типов связей и истории атрибутов
| Индекс | Поля | Сценарий |
|--------|------|----------|
| `idx_relation_type` | `relation_type` | "Найти все связи типа 'price'" |
| `idx_parent_relation` | `parent`, `relation_type` | **Динамические атрибуты**: "Все цены товара X" |
| `idx_parent_relation_time` | `parent`, `relation_type`, `time` | **История атрибутов**: "Цена товара X на дату Y" |

### Индексы для текстовых ссылок
| Индекс | Поля | Назначение |
|--------|------|------------|
| `idx_text_key` | `text_key` | Поиск связей по ключу текста |
| `idx_text_id` | `text_id` | Поиск связей по ID текста |

### Технические индексы
| Индекс | Поля | Назначение |
|--------|------|------------|
| `idx_hash` | `hash(64)` | Быстрое сравнение связей по хешу |
| `idx_created_at` | `created_at` | Сортировка по времени создания записи |

## 🎯 Ключевые улучшения

### 1. **Оптимизация фильтров по типу**
Раньше запрос вида:
```sql
SELECT * FROM neuron WHERE type='job' AND job_status='pending'
```
использовал только индекс по `job_status`, затем фильтровал по `type`.

Теперь индекс `idx_job_status_type` позволяет сразу отсечь лишние типы:
```sql
INDEX `idx_job_status_type` (`type`, `job_status`, `job_queue`)
```

### 2. **Историчность данных в synapse**
Для получения актуального значения атрибута на дату:
```sql
SELECT data 
FROM synapse 
WHERE parent = ? 
  AND relation_type = 'price' 
  AND time <= '2024-01-15' 
ORDER BY time DESC 
LIMIT 1
```
Индекс `idx_parent_relation_time` делает этот запрос мгновенным даже на миллионах записей.

### 3. **Композитные индексы для иерархии**
Запрос каталога товаров:
```sql
SELECT * FROM neuron 
WHERE pid = 123 
  AND type = 'item' 
ORDER BY sort
```
Использует индекс `idx_pid_type` + `idx_pid_sort` для полного покрытия.

## 📈 Рекомендации по использованию

### Для разработчиков

1. **Всегда указывайте `type` в запросах к `neuron`**
   ```php
   // ❌ Медленно
   $repo->findBy(['pid' => $parentId]);
   
   // ✅ Быстро
   $repo->findBy(['pid' => $parentId, 'type' => 'item']);
   ```

2. **Используйте композитные условия в порядке индекса**
   ```php
   // Индекс: (type, event_is_active, event_name)
   // ✅ Правильный порядок
   $events = $neuronRepo->findBy([
       'type' => 'event_listener',
       'event_is_active' => 1,
       'event_name' => 'user.created'
   ]);
   ```

3. **Для истории атрибутов всегда фильтруйте по времени**
   ```php
   // Получение цены на конкретную дату
   $synapse = $db->fetchAssociative(
       "SELECT * FROM synapse 
        WHERE parent = ? 
          AND relation_type = 'price' 
          AND time <= ? 
        ORDER BY time DESC 
        LIMIT 1",
       [$productId, $date]
   );
   ```

### Для администраторов БД

1. **Мониторинг размера индексов**
   ```sql
   SELECT 
       table_name,
       index_name,
       ROUND(stat_value * @@innodb_page_size / 1024 / 1024, 2) AS size_mb
   FROM mysql.innodb_index_stats 
   WHERE database_name = 'trinity' 
     AND stat_name = 'size'
   ORDER BY size_mb DESC;
   ```

2. **Анализ использования индексов**
   ```sql
   SELECT * FROM sys.schema_unused_indexes 
   WHERE object_schema = 'trinity';
   ```

3. **Оптимизация таблицы после массового импорта**
   ```sql
   OPTIMIZE TABLE neuron;
   OPTIMIZE TABLE synapse;
   ANALYZE TABLE neuron, synapse;
   ```

## 🔧 Миграция

Для применения новых индексов на существующей базе:

```sql
-- Выполните обновлённый database.sql
source /path/to/database.sql;

-- Или создайте индексы вручную:
ALTER TABLE neuron ADD INDEX `idx_date` (`date`);
ALTER TABLE neuron ADD INDEX `idx_pid_type` (`pid`, `type`);
-- ... и так далее по списку выше

ALTER TABLE synapse ADD INDEX `idx_time` (`time`);
ALTER TABLE synapse ADD INDEX `idx_parent_child_time` (`parent`, `child`, `time`);
-- ... и так далее
```

⚠️ **Внимание**: Создание индексов на больших таблицах может занять время. Рекомендуется выполнять в период низкой нагрузки.
