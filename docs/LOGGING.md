# 📝 Система логирования Trinity Core

## Обзор

Система логирования реализована в соответствии со стандартом **PSR-3** и предоставляет удобный способ записи событий работы приложения.

## Структура

```
src/Services/Logger.php    # Основной класс логгера
var/logs/                  # Директория для файлов логов
├── error.log              # Ошибки (error, critical, alert, emergency)
├── warning.log            # Предупреждения
└── general.log            # Общая информация (debug, info, notice)
```

## Уровни логирования

| Уровень | Константа | Описание |
|---------|-----------|----------|
| `emergency` | `LogLevel::EMERGENCY` | Система неработоспособна |
| `alert` | `LogLevel::ALERT` | Требуется немедленное действие |
| `critical` | `LogLevel::CRITICAL` | Критические условия |
| `error` | `LogLevel::ERROR` | Ошибки времени выполнения |
| `warning` | `LogLevel::WARNING` | Предупреждения |
| `notice` | `LogLevel::NOTICE` | Нормальные, но значимые события |
| `info` | `LogLevel::INFO` | Информационные сообщения |
| `debug` | `LogLevel::DEBUG` | Отладочная информация |

## Использование

### В контроллерах и сервисах

```php
use Jan\Trinity\Core\Services\Logger;
use Psr\Log\LogLevel;

class MyController
{
    public function __construct(
        private Logger $logger
    ) {}
    
    public function doSomething(): void
    {
        // Простое сообщение
        $this->logger->info('Пользователь выполнил действие');
        
        // Сообщение с контекстом (интерполяция переменных)
        $this->logger->info('Пользователь {user_id} вошёл в систему', [
            'user_id' => 123
        ]);
        
        // Ошибка
        $this->logger->error('Не удалось сохранить данные: {message}', [
            'message' => $e->getMessage()
        ]);
        
        // Предупреждение
        $this->logger->warning('Попытка доступа к несуществующей странице: {uri}', [
            'uri' => $_SERVER['REQUEST_URI']
        ]);
    }
}
```

### Автоматическое логирование в ядре

Ядро автоматически логирует:
- **404 ошибки** — страница не найдена (уровень `warning`)
- **405 ошибок** — метод не разрешён (уровень `warning`)
- **500 ошибок** — критические ошибки (уровень `error`)

## Конфигурация

### Переменные окружения (.env)

```bash
# Уровень логирования (все сообщения этого уровня и выше будут записаны)
LOG_LEVEL=debug

# Путь к логам задаётся в config/container.php (по умолчанию var/logs)
```

### Доступные уровни в .env

- `debug` — все сообщения (для разработки)
- `info` — информация и выше
- `notice` — заметные события и выше
- `warning` — предупреждения и выше
- `error` — только ошибки (для продакшена)
- `critical` — только критические ошибки
- `alert` — только тревоги
- `emergency` — только экстренные случаи

## Формат записи

```
[2025-01-15 14:30:45] [ERROR] Критическая ошибка: Connection failed
[2025-01-15 14:30:46] [WARNING] Страница не найдена: /admin/missing
[2025-01-15 14:30:47] [INFO] Пользователь 123 вошёл в систему
```

## Интерполяция переменных

Логгер поддерживает подстановку переменных в сообщения:

```php
$logger->info('Заказ {order_id} на сумму {amount} создан', [
    'order_id' => 456,
    'amount' => 1500.00
]);
// Результат: Заказ 456 на сумму 1500 создан
```

## Безопасность

- Логгер игнорирует объекты (например, исключения) в контексте
- Поддерживаются только скалярные типы и Stringable
- Ключ `exception` пропускается при интерполяции

## Рекомендации

### Для разработки
```bash
LOG_LEVEL=debug
```

### Для продакшена
```bash
LOG_LEVEL=warning
```

### Для высоконагруженных систем
```bash
LOG_LEVEL=error
```

## Интеграция с плагином Monitor

При возникновении критических ошибок ядро:
1. Записывает ошибку в лог (`error.log`)
2. Пытается отобразить страницу ошибки через `MonitorController`
3. Если Monitor недоступен — возвращает простой HTTP-ответ

## Расширение

Для добавления собственных обработчиков логов расширьте класс `Logger` или создайте новый, реализующий `Psr\Log\LoggerInterface`.
